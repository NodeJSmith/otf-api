## Objectives & Success Criteria

The `src/otf_api/anonymize/` package exists with two foundational modules: field mappings covering all PII fields found in the 67 captured fixtures, and seeded Faker-backed generators for each PII category. Unit tests confirm every known PII field has a mapping and every generator produces values of the correct type, format, and range.

## Out of Scope

- `Anonymizer`, `AnonymizeConfig`, and `validate_anonymized` are stub-only exports in `__init__.py` — their implementation is deferred to WP02-WP04
- No file I/O, no batch processing, no fixture handling
- No integration with the HTTP client

## Test Strategy

Tests in `tests/test_anonymize/test_mappings.py` and `tests/test_anonymize/test_generators.py`. All tests are pure unit tests with no network or file I/O. The mapping coverage test uses a hardcoded set of field names derived from the PII audit.

## Review Guidance

- Verify the field mapping list is complete against the PII audit in the research brief. Missing a field means PII leaks.
- Verify generators produce the correct types — a `fake_uuid()` that returns an int would break model parsing.
- Verify the `KNOWN_SAFE_FIELDS` set doesn't accidentally include any PII fields.
- The `faker` dependency must be a runtime dep (not dev-only) per the design doc.
