## Objectives & Success Criteria

The `Anonymizer` class exists and can process a raw JSON dict, recursively walking the structure and applying replacements based on the field mappings from WP01. The `ReplacementMap` maintains referential integrity across multiple calls. `AnonymizeConfig` controls strictness level. Unit tests verify correct replacement, null preservation, referential integrity, and strictness modes.

## Subtasks

1. Create `src/otf_api/anonymize/anonymizer.py`:
   - `AnonymizeConfig` dataclass with: `seed: int | None`, `strictness: Literal["permissive", "mask", "drop"]`, `output_dir: Path | None`
   - `ReplacementMap` class wrapping `dict[str, str]` with thread-safe access (`threading.Lock`):
     - `get_or_create(real_value: str, generator: Callable) -> str` — returns existing fake or generates new one
     - `to_json() -> dict` — serializable form (maps fake → field position, not real values)
     - `from_json(data: dict) -> ReplacementMap` — deserialize
   - `Anonymizer` class:
     - `__init__(config: AnonymizeConfig, generators: FakeDataGenerators, mappings: list[FieldMapping])`
     - `anonymize_dict(data: dict, context: str = "") -> dict` — recursively walk JSON, apply mappings. Context is the endpoint path for logging.
     - `anonymize_value(key: str, value: Any) -> Any` — look up key in mappings, apply strategy. Null → null. Unknown → pass through (permissive), mask (strict-mask), or drop (strict-drop).
     - `anonymize_url(url: str) -> str` — replace PII in URL paths and query params using the replacement map
     - `anonymize_filename(filename: str) -> str` — replace PII in fixture filenames using the replacement map
     - Internal: `_walk_dict`, `_walk_list` for recursive traversal
     - Body composition handling: detect scan objects by field presence (e.g., `tbw` + `bfm` + `lbm` present), generate one `body_comp_factor` per scan, apply to all fields
     - Telemetry handling: detect telemetry arrays by structure, generate one `hr_delta` per workout, apply to all HR values and zone boundaries
     - Address correlation: when anonymizing address fields, use the parent object's identifier (e.g., `studioUUId`) as a correlation key to ensure all format variants of the same address map to the same fake address
2. Update `src/otf_api/anonymize/__init__.py` — export `Anonymizer`, `AnonymizeConfig`, `ReplacementMap`
3. Write `tests/test_anonymize/test_anonymizer.py`:
   - `test_replaces_known_pii_field` — a dict with `{"firstName": "Jessica"}` produces a different name
   - `test_preserves_null` — `{"workPhone": null}` stays null
   - `test_preserves_unknown_field_permissive` — unknown field passes through in permissive mode
   - `test_masks_unknown_field_strict` — unknown field gets sentinel in mask mode
   - `test_drops_unknown_field_strict` — unknown field is removed (key preserved in manifest) in drop mode
   - `test_referential_integrity_across_calls` — same UUID in two `anonymize_dict` calls produces same fake
   - `test_nested_dict_walk` — deeply nested structure is fully walked
   - `test_list_walk` — lists of dicts are each processed
   - `test_body_comp_scaling` — all body comp fields scaled by same factor
   - `test_hr_zone_recalculation` — zones derived from anonymized maxHr
   - `test_anonymize_url` — member UUID in URL path is replaced
   - `test_anonymize_url_query_params` — email in query param is replaced
   - `test_anonymize_filename` — PII in filename is replaced
   - `test_address_correlation` — same studio UUID + different address formats produce same fake address
   - `test_redacted_sentinel` — studioToken becomes "REDACTED"
   - `test_replacement_map_serialization` — map serializes and deserializes correctly
   - `test_replacement_map_thread_safety` — concurrent access from multiple threads doesn't corrupt the map
   - `test_faker_failure_fallback` — mock a generator to raise, verify the anonymizer returns a deterministic placeholder (not the real value)

## Test Strategy

Tests in `tests/test_anonymize/test_anonymizer.py`. Unit tests use small handcrafted JSON dicts, not full fixture files. Thread safety test uses `concurrent.futures.ThreadPoolExecutor`. No network or file I/O.

## Review Guidance

- Verify the recursive walk handles all three JSON wrapper formats: `{"code": "SUCCESS", "data": {...}}`, `{"items": [...]}`, and flat objects
- Verify body composition detection is robust (checks for presence of multiple related fields, not just one)
- Verify address correlation uses the parent identifier, not string matching
- The `ReplacementMap` lock must be acquired for both read and write operations
- Verify the anonymizer never returns a real PII value even when the generator fails (design doc edge case 12)
