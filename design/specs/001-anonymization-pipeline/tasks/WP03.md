## Objectives & Success Criteria

The `Anonymizer` handles the three domain-specific transform categories that require specialized logic beyond simple field replacement: body composition scaling (preserving mathematical relationships between ~50 fields), heart rate telemetry offsetting (recalculating zone boundaries from anonymized maxHr), and address format correlation (ensuring different text representations of the same physical address map to the same fake address). Unit tests verify each transform independently.

## Out of Scope

- Generic field replacement, null handling, strictness modes — already implemented in WP02
- File I/O, batch mode, real-time capture — deferred to WP05/WP06
- The PII validator — deferred to WP04

## Subtasks

1. Add body composition transform to `src/otf_api/anonymize/anonymizer.py`:
   - Detection: identify scan objects by field presence (e.g., `tbw` + `bfm` + `lbm` all present in the same dict)
   - Generate one `body_comp_factor` per scan (via `generators.fake_body_comp_factor()`)
   - Apply the factor to all body comp fields in the scan, preserving ratios (lean mass + fat mass ≈ total weight)
   - Handle derived fields: `bmi` recalculated from anonymized weight/height, `pbf` from anonymized bfm/weight
2. Add telemetry transform to `src/otf_api/anonymize/anonymizer.py`:
   - Detection: identify telemetry arrays by structure (list of dicts with `hr` and `relative_timestamp` keys)
   - Generate one `hr_delta` per workout (via `generators.fake_hr_delta()`)
   - Offset all HR values by the delta
   - Recalculate zone boundaries from the anonymized `maxHr` (zones are derived as percentages of maxHr)
3. Add address correlation to `src/otf_api/anonymize/anonymizer.py`:
   - When anonymizing address fields, use the parent object's identifier (e.g., `studioUUId` in the same dict or a parent dict) as a correlation key
   - The `ReplacementMap` stores address groups keyed by `(identifier, "address")` so all format variants of the same address map to the same fake address
   - Fallback: if no parent identifier is found, fall back to direct string matching in the replacement map
4. Write `tests/test_anonymize/test_domain_transforms.py`:
   - `test_body_comp_scaling_preserves_ratios` — lean mass + fat mass ≈ total weight before and after
   - `test_body_comp_consistent_factor_per_scan` — all fields in one scan use the same factor
   - `test_body_comp_different_factor_per_scan` — two different scans get different factors
   - `test_hr_zone_recalculation` — zones are derived from anonymized maxHr, not original
   - `test_hr_delta_consistent_per_workout` — all HR values in one telemetry array offset by same delta
   - `test_hr_delta_different_per_workout` — two workouts get different deltas
   - `test_address_correlation_same_studio` — same studio UUID + different address text → same fake address
   - `test_address_correlation_no_identifier_fallback` — without a parent identifier, falls back to exact string matching

Run tests with: `timeout 300 uv run pytest tests/test_anonymize/test_domain_transforms.py`

## Test Strategy

Tests in `tests/test_anonymize/test_domain_transforms.py`. Unit tests use handcrafted dicts mimicking real fixture structures (body comp scan objects, telemetry arrays, studio-with-address objects). No network or file I/O.

## Review Guidance

- Body comp detection must check for multiple related fields (not just `tbw` alone) to avoid false positives
- The BMI recalculation must use the formula: `bmi = weight_kg / (height_m ** 2)` — verify the anonymized weight/height are converted to metric before calculating
- Zone boundaries must be derived as percentages of maxHr, matching the OTF zone system (gray: <62%, blue: 62-72%, green: 72-84%, orange: 84-92%, red: 92-100%)
- Address correlation must handle the case where the parent identifier has already been anonymized (look up both the real and fake identifier in the map)
