## Objectives & Success Criteria

A batch anonymization command processes the full 67-file fixture corpus, producing anonymized output where: the PII validator reports zero leaks, all anonymized files parse through Pydantic models, referential integrity is maintained across all files, filenames are anonymized, and the replacement map is serialized. This is the integration test that proves the full pipeline works end-to-end.

## Subtasks

1. Create `scripts/anonymize_fixtures.py` — batch mode entry point:
   - Accepts `input_dir` and `output_dir` as arguments (defaults: `fixtures/raw_responses` → `fixtures/anonymized`)
   - Reads `_meta.json` from the input directory for endpoint metadata
   - Instantiates `Anonymizer` with default config (seed derived from first member UUID found)
   - Processes each JSON file: reads, anonymizes body, anonymizes filename, writes to output dir
   - Skips malformed JSON files with a warning (edge case 11) — logs the filename and continues
   - On write failure (disk full, permission error): removes the partial output directory and exits with a clear error message (edge case 10)
   - Anonymizes `_meta.json` itself (PII in `params` and `file` fields)
   - Writes `_anonymization_map.json` alongside output
   - Runs the PII validator on the full output
   - Prints a summary: files processed, skipped (malformed), leaks found, model parse errors, referential integrity checks
2. Add `fixtures/anonymized/` to `.gitignore` (anonymized fixtures will be committed separately after manual review, not auto-committed by the script)
3. Write `tests/test_anonymize/test_batch_integration.py`:
   - These tests require the raw fixture files to be present locally (skip with `pytest.mark.skipif` if `fixtures/raw_responses/` doesn't exist)
   - `test_full_batch_zero_leaks` — run the anonymizer on all 67 files, run the validator, assert zero leaks
   - `test_full_batch_models_parse` — all anonymized files parse through their corresponding Pydantic models
   - `test_full_batch_referential_integrity` — the member UUID appears in the same number of output files as input files, and is the same fake UUID everywhere
   - `test_full_batch_nulls_preserved` — spot-check known null fields (e.g., `workPhone`, `profilePictureUrl` in member detail) remain null
   - `test_full_batch_filenames_anonymized` — no output filename contains the real member UUID, email, or phone number
   - `test_full_batch_meta_anonymized` — `_meta.json` in output has no real PII in `params` or `file` fields
   - `test_full_batch_determinism` — run the anonymizer twice with the same seed, assert byte-identical output
   - `test_full_batch_replacement_map_written` — `_anonymization_map.json` exists and is valid JSON
   - `test_address_format_variants_consistent` — the studio address (which appears in different formats across booking v1 and v2 responses) maps to the same fake address in both
   - `test_malformed_json_skipped` — create a fixture file with invalid JSON, run batch, verify it's skipped with a warning and other files still process
   - `test_disk_full_cleanup` — mock `Path.write_text` to raise `OSError`, verify the partial output directory is removed and the error message is clear
4. Update `src/otf_api/anonymize/__init__.py` — export `anonymize_batch` convenience function

## Test Strategy

Tests in `tests/test_anonymize/test_batch_integration.py`. These are integration tests that process real fixture files. They require `fixtures/raw_responses/` to be present (skipped in CI where fixtures aren't available). This is the primary validation that the anonymizer works correctly against real API data — the unit tests in WP01-WP03 test components in isolation.

## Review Guidance

- This is the most critical WP — it proves the anonymizer actually works on real data
- The fixture-absent skip must use `pytest.mark.skipif`, not silently pass — CI should be aware these tests exist but were skipped
- The determinism test must compare file contents, not just file counts
- The address format variant test specifically targets the edge case the user flagged
- Verify the batch script handles the three different host directories and their different response shapes
- The replacement map must NOT contain real PII values — verify it maps fake→position, not fake→real
