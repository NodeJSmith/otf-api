## Objectives & Success Criteria

End users can set `OTF_ANONYMIZE_RESPONSES=true` and the library automatically captures and anonymizes all API responses to a debug output directory during normal usage. The hook integrates into `OtfClient.__init__` without affecting normal behavior when disabled. The output directory, seed, and strictness are configurable via environment variables.

## Subtasks

1. Create `src/otf_api/anonymize/hooks.py`:
   - `AnonymizedCaptureHook` class:
     - `__init__(anonymizer: Anonymizer, output_dir: Path)` — session-scoped, reuses the anonymizer instance for referential integrity
     - `__call__(response: httpx.Response) -> None` — the httpx event hook. Reads the response, anonymizes the JSON body, anonymizes the request URL, writes to `output_dir/<host>/<slugified-path>.json`. Handles non-JSON responses gracefully (skip with warning).
     - On first call: write a `_capture_start.json` with timestamp and config
     - On errors: log warning, do not raise (capture must never break the library)
   - `create_capture_hook(config: AnonymizeConfig | None = None) -> AnonymizedCaptureHook` — factory that reads env vars:
     - `OTF_ANONYMIZE_RESPONSES` — `true` to enable (default: disabled)
     - `OTF_ANONYMIZE_OUTPUT_DIR` — override output directory (default: `platformdirs.user_cache_dir("otf-api") / "debug"`)
     - `OTF_ANONYMIZE_SEED` — override seed (default: derived from member UUID)
     - `OTF_ANONYMIZE_STRICTNESS` — `permissive`, `mask`, or `drop` (default: `permissive`)
2. Modify `src/otf_api/api/client.py` — in `OtfClient.__init__` (after line 53), add conditional hook injection:
   - Check `os.getenv("OTF_ANONYMIZE_RESPONSES", "false").lower() == "true"`
   - If enabled, import `create_capture_hook` from `otf_api.anonymize.hooks` (lazy import to avoid pulling in Faker when anonymization is disabled)
   - Append the hook to `self.session.event_hooks["response"]`
   - Store the hook instance as `self._anonymize_hook` for access to the anonymizer/replacement map
   - The lazy import is justified here: it's a conditional branch guarded by an env var, and importing `anonymize.hooks` pulls in Faker which adds ~200ms to import time. Normal library users who don't set the env var should not pay this cost.
3. Update `src/otf_api/__init__.py` — add `Anonymizer` and `AnonymizeConfig` to `__all__`
4. Update `pyproject.toml` — ensure `faker` is in the main dependencies (done in WP01, verify here)
5. Write `tests/test_anonymize/test_hooks.py`:
   - `test_hook_not_injected_by_default` — verify `OtfClient` does not have `_anonymize_hook` when env var is not set (use monkeypatch to ensure env var is unset)
   - `test_hook_writes_anonymized_output` — create a mock httpx.Response, call the hook, verify anonymized JSON was written to the output directory with no real PII
   - `test_hook_handles_non_json_response` — response with non-JSON content type is skipped without error
   - `test_hook_error_does_not_propagate` — if the anonymizer raises, the hook catches and logs, does not re-raise
   - `test_capture_start_json_written` — first hook invocation writes `_capture_start.json`
   - `test_env_var_config_parsing` — verify `create_capture_hook` reads all 4 env vars correctly
6. Write `tests/test_anonymize/test_client_integration.py`:
   - `test_env_var_injects_hook` — with `OTF_ANONYMIZE_RESPONSES=true` monkeypatched, verify `OtfClient` has the hook in `session.event_hooks["response"]` (requires mocking the auth flow to avoid real credential requirement)
   - `test_env_var_disabled_no_hook` — with env var unset or `false`, verify no hook

## Test Strategy

Tests in `tests/test_anonymize/test_hooks.py` and `tests/test_anonymize/test_client_integration.py`. Hook tests use mock httpx.Response objects — no real HTTP calls. Client integration tests monkeypatch the env var and mock `OtfUser` to avoid credential requirements. All tests are offline.

## Review Guidance

- The lazy import in `client.py` is the ONE exception to the "no lazy imports" rule — justified by the 200ms Faker import cost for a feature most users won't enable. Verify the import is inside the `if` branch only.
- Verify the hook NEVER raises — any error must be caught and logged. A broken anonymizer must never break the library.
- Verify the hook doesn't modify the actual httpx.Response — it must be observational only
- Verify the env var check uses `.lower() == "true"` consistent with the existing `OTF_LOG_RAW_RESPONSE` pattern
- The client integration test must work without real OTF credentials
