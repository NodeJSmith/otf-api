## Objectives & Success Criteria

Every public read-only method in `MemberApi` and `StudioApi` has at least one test that calls it through the mock transport and asserts the return value is the correct Pydantic model type with key fields verified. All tests pass with `uv run pytest tests/test_api/test_members.py tests/test_api/test_studios.py -v`.

## Subtasks

1. Create `tests/test_api/test_members.py` with tests for all 5 read-only member methods:
   - `test_get_member_detail` — asserts `MemberDetail` returned, `member_uuid` is a string, `email_address` is a string. Note: this method internally calls `get_studio_detail` for the home studio — the mock transport must have the corresponding studio fixture route registered (handled by WP01's route registration from index.json).
   - `test_get_member_membership` — asserts `MemberMembership` returned
   - `test_get_member_purchases` — asserts `list[MemberPurchase]` returned, list is non-empty
   - `test_get_sms_notification_settings` — asserts `SmsNotificationSettings` returned
   - `test_get_email_notification_settings` — asserts `EmailNotificationSettings` returned
2. Create `tests/test_api/test_studios.py` with tests for all 4 read-only studio methods (skip `get_studios_by_geo` — it's an alias for `search_studios_by_geo`):
   - `test_get_studio_detail` — asserts `StudioDetail` returned, has a `studio_name` string
   - `test_search_studios_by_geo` — asserts `list[StudioDetail]` returned, list is non-empty
   - `test_get_favorite_studios` — asserts `list[StudioDetail]` returned
   - `test_get_studio_services` — asserts `list[StudioService]` returned

## Test Strategy

- `tests/test_api/test_members.py` — 5 tests covering all read-only MemberApi methods. Each test uses the `mock_otf` fixture from WP01.
- `tests/test_api/test_studios.py` — 4 tests covering all read-only StudioApi methods.
- Run: `timeout 300 uv run pytest tests/test_api/test_members.py tests/test_api/test_studios.py -v`

## Review Guidance

- Every public read-only method in MemberApi and StudioApi must have a corresponding test — verify none are missing
- Tests must assert on model type AND at least one key field — a bare `isinstance` check is insufficient
- Tests must not set `OTF_EMAIL` or `OTF_PASSWORD` environment variables
- If any test requires a fixture that doesn't exist, that's a blocker — all needed fixtures were captured in the data collection phase
