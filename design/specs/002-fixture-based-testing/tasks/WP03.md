## Objectives & Success Criteria

Every public read-only method in `BookingApi` has at least one test that calls it through the mock transport and asserts correct Pydantic model parsing. Methods that require a pre-existing Booking or OtfClass object as input are tested by first parsing one from fixtures. All tests pass with `uv run pytest tests/test_api/test_bookings.py -v`.

## Subtasks

1. Create `tests/test_api/test_bookings.py` with tests for read-only booking methods:
   - `test_get_classes` — asserts `list[OtfClass]` returned, list is non-empty, first item has `class_uuid` string
   - `test_get_bookings` — asserts `list[Booking]` returned
   - `test_get_bookings_new` — asserts `list[BookingV2]` returned, exercises the date-range parameter variant
   - `test_get_bookings_new_by_date` — asserts `dict` returned with datetime keys and `BookingV2` values (calls same endpoint as `get_bookings_new`)
2. For methods that take a Booking/OtfClass argument (`get_booking_from_class`, `get_class_from_booking`, etc.), test them by constructing the input object from a fixture first, then calling the method. If the fixture data doesn't support this (e.g., the booking fixture doesn't contain a class UUID that matches a class fixture), note which methods couldn't be tested and why.

## Test Strategy

- `tests/test_api/test_bookings.py` — tests for all feasible read-only BookingApi methods. Primary focus on the 4 methods with direct fixture support. Secondary tests for chained methods (get_class_from_booking, get_booking_from_class) if fixture cross-references align.
- Run: `timeout 300 uv run pytest tests/test_api/test_bookings.py -v`

## Review Guidance

- The `get_bookings_new` and `get_bookings_new_by_date` methods hit the same HTTP endpoint — verify the mock doesn't break when the same route is hit twice in different tests
- Booking methods use two different API hosts (`api.orangetheory.co` for old endpoints, `api.orangetheory.io` for new) — verify both are routed correctly
- If any chained method (e.g., `get_class_from_booking`) can't be tested due to fixture cross-reference gaps, document it explicitly rather than silently skipping
