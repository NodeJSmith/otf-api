## Objectives & Success Criteria

Every public read-only method in `WorkoutApi` has at least one test that calls it through the mock transport and asserts correct Pydantic model parsing. Parameterized endpoints (benchmarks by equipment, benchmarks by challenge category) are tested with at least one variant each. Telemetry and performance summary endpoints are tested using the multi-fixture pattern (multiple responses for the same URL pattern). All tests pass with `uv run pytest tests/test_api/test_workouts.py -v`.

## Subtasks

1. Create `tests/test_api/test_workouts.py` with tests for all read-only workout methods:
   - `test_get_workouts` — asserts `list[Workout]` returned, list is non-empty
   - `test_get_body_composition_list` — asserts `list[BodyCompositionData]` returned. Note: this endpoint uses `cognito_id` (not `member_uuid`) in the URL path (`/member/members/{cognito_id}/body-composition`). The mock user's `cognito_id` must match the UUID in the fixture (`23b8c1e9-3924-46de-beb1-3b9046685257`).
   - `test_get_challenge_tracker` — asserts `ChallengeTracker` returned
   - `test_get_benchmarks_by_equipment` — asserts `list[FitnessBenchmark]` returned, uses `EquipmentType.Treadmill` as test case
   - `test_get_benchmarks_by_challenge_category` — asserts `list[FitnessBenchmark]` returned, uses `ChallengeCategory.DriTri` as test case
   - `test_get_challenge_tracker_detail` — asserts `FitnessBenchmark` returned, uses `ChallengeCategory.DriTri`
   - `test_get_hr_history` — asserts `list[TelemetryHistoryItem]` returned
   - `test_get_telemetry` — asserts `Telemetry` returned, needs a `performance_summary_id` from one of the telemetry fixtures
   - `test_get_member_lifetime_stats_in_studio` — asserts `InStudioStatsData` returned
   - `test_get_member_lifetime_stats_in_studio_this_month` — asserts same type, exercises `StatsTime.ThisMonth` parameter
   - `test_get_member_lifetime_stats_out_of_studio` — asserts `OutStudioStatsData` returned
   - `test_get_out_of_studio_workout_history` — asserts `list[OutOfStudioWorkoutHistory]` returned

## Test Strategy

- `tests/test_api/test_workouts.py` — 12 tests covering all read-only WorkoutApi methods. Uses fixtures from `workouts/` subdirectory (51 files). Parameterized benchmarks tested with one representative variant each (Treadmill, DriTri).
- Run: `timeout 300 uv run pytest tests/test_api/test_workouts.py -v`

## Review Guidance

- WorkoutApi hits three different API hosts (`api.orangetheory.co`, `api.orangetheory.io`, `api.yuzu.orangetheory.com`) — verify all three are routed correctly in the mock
- The `get_workouts` method internally fetches multiple performance summaries and telemetry data — verify the mock serves all sub-requests. If the method makes requests for UUIDs not in the fixtures, the test may need to be adjusted to match available fixture data.
- Benchmark tests use enum values (`EquipmentType`, `ChallengeCategory`) — verify the correct enum values map to the correct query parameters in the fixture index
- The `get_lifetime_stats_in_studio` and `get_lifetime_stats_out_of_studio` methods hit the same URL path (`/performance/v2/{uuid}/over-time/allTime`) — verify the mock can serve both (two fixtures exist: `get_lifetime_stats__allTime.json` and `get_lifetime_stats__allTime__2.json`)
