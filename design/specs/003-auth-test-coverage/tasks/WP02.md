## Objectives & Success Criteria

- `tests/test_auth/test_cache.py` covers `src/otf_api/cache.py` (`OtfCache` methods) at 80%+
- Cache round-trip, expiry, and selective clearing are all verified
- All tests use `tmp_path`-backed `OtfCache` instances — no reads/writes to the real user cache directory
- All tests pass without network access or real credentials

## Subtasks

1. Add a `tmp_cache` fixture to `tests/test_auth/conftest.py`: instantiate `OtfCache(tmp_path)` directly (not via `get_cache()`) for a fresh, isolated, filesystem-backed cache per test
2. Test `write_device_data_to_cache` / `read_device_data_from_cache` round-trip: write device data dict with all three keys (`device_key`, `device_group_key`, `device_password`), read back, assert equality
3. Test device data write with all-empty values: write `{"device_key": "", "device_group_key": "", "device_password": ""}` → `read_device_data_from_cache` returns `{}`
4. Test `write_token_data_to_cache` / `read_token_data_from_cache` round-trip: write token data, read back immediately, assert equality
5. Test token data expiry: write token data with `expiration=1` (1 second), sleep 2 seconds, read back → returns `{}`
6. Test token data write with all-empty values: write empty token values → `read_token_data_from_cache` returns `{}`
7. Test `clear_tokens`: write both token and device data, call `clear_tokens()`, assert tokens are gone but device data remains
8. Test `clear_device_data`: write both, call `clear_device_data()`, assert device data is gone but tokens remain
9. Test `clear`: write both, call `clear()`, assert everything is gone

## Test Strategy

All tests in `tests/test_auth/test_cache.py`:

- `test_device_data_round_trip` — verifies write/read identity for device data
- `test_device_data_all_empty_returns_empty_dict` — verifies empty-value guard
- `test_token_data_round_trip` — verifies write/read identity for token data
- `test_token_data_expiry` — verifies expired tokens are not returned
- `test_token_data_all_empty_returns_empty_dict` — verifies empty-value guard
- `test_clear_tokens_preserves_device_data` — verifies selective clearing
- `test_clear_device_data_preserves_tokens` — verifies selective clearing
- `test_clear_removes_everything` — verifies full clear

## Review Guidance

- **Isolation**: Every test must use the `tmp_cache` fixture, never `get_cache()`. The real cache directory must not be touched.
- **Expiry test**: The 1-second expiry + 2-second sleep is acceptable for a unit test. If flaky, increase to 2s/3s — do not remove the test.
- **Edge case coverage**: The empty-value tests verify the `if not any(values())` guard paths in both write and read methods. These must be present.
- **No mocking of `diskcache` internals**: Tests exercise the real `diskcache.Cache` filesystem operations against `tmp_path`. This is intentional — mocking the cache's own storage would defeat the purpose.
