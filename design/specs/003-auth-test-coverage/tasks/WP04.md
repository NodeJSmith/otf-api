4. ## Test Strategy

Tests in `tests/test_auth/test_httpx_auth.py`:

- `test_auth_flow_standard_request` — verifies Bearer token header injection and check_token called
- `test_auth_flow_sigv4_branch` — verifies SIGV4AUTH_REQUIRED header removal and sign flow dispatch
- `test_auth_flow_token_not_string` — verifies ValueError guard
- `test_sign_httpx_request` — verifies SigV4 signing produces correct header format
- `test_sign_httpx_request_streaming_body` — verifies ValueError for streaming bodies

Tests in `tests/test_auth/test_otf_user.py`:

- `test_otf_user_init_happy_path` — verifies identity field extraction from cognito claims
- `test_otf_user_init_no_credentials_fallback` — verifies env var fallback on NoCredentialsError
- `test_otf_user_init_unexpected_error_propagates` — verifies non-auth errors bubble up

## Review Guidance

- **SigV4 real execution**: The `sign_httpx_request` test lets `botocore.auth.SigV4Auth` run with mock credentials. This is intentional — it verifies the integration with botocore's signing logic. Do not mock SigV4Auth itself.
- **auth_flow generator protocol**: `auth_flow` is a generator that yields requests. Tests must consume it via `list()` or `next()` to actually execute the flow. Simply calling `auth.auth_flow(request)` without consuming does nothing.
- **OtfUser mock isolation**: The `OtfCognito` mock for OtfUser tests must be patched at `otf_api.auth.user.OtfCognito` (the import location), not `otf_api.auth.auth.OtfCognito`.
- **Fallback test ordering**: The NoCredentialsError fallback test must verify the exact call sequence — first call raises, then `get_username_password` is called, then second `OtfCognito` call succeeds with the returned credentials.
- **SigV4 Bearer header note**: `auth_flow` sets `Authorization: Bearer ...` before the `SIGV4AUTH_REQUIRED` check. `sign_httpx_request` copies headers and only removes `connection` — the pre-set Bearer token header survives into the signed request and gets overwritten by `SigV4Auth.add_auth()`. This is not a bug (SigV4 replaces the Authorization header), but the test should verify the final `Authorization` header starts with `AWS4-HMAC-SHA256`, confirming the Bearer value was replaced.
