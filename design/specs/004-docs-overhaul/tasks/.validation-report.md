### Contradictions

#### CONTRADICTION-1 (HIGH): Exception count mismatch — T02 implements 11, design doc specifies 12

**Design doc location:** `## Architecture` → `### Source code changes`
> "**`src/otf_api/exceptions.py`**: Add `__all__` listing all 12 exception classes"

**T02 Prompt (the `__all__` it implements):**
```python
__all__ = [
    "OtfError", "OtfRequestError", "RetryableOtfRequestError",
    "BookingError", "AlreadyBookedError", "ConflictingBookingError",
    "BookingAlreadyCancelledError", "OutsideSchedulingWindowError",
    "ResourceNotFoundError", "AlreadyRatedError", "ClassNotRatableError",
]
```
This is 11 entries. T02's Summary says "all 11 exception classes" and T02's Verify item says "`__all__` contains exactly 11 entries."

**T02 Focus** explains the discrepancy: "`NoCredentialsError` in `src/otf_api/auth/auth.py` — this is NOT exported and should NOT be added here (it's internal to the auth flow)."

The design doc's "12" appears to be an error in the design doc (or there is a 12th exception class the planner identified that T02's Focus correctly excluded). The T02 task gives a reasoned justification for 11. However, the implementation is in direct numeric conflict with the design doc's stated target. The executor must read the design doc number ("12") and then T02's explicit instruction ("11") and will face a contradiction. **This must be resolved** — either the design doc should be updated to say 11, or T02 must add the 12th exception to its `__all__`.

#### CONTRADICTION-2 (MEDIUM): AC#9 Verify criterion is weaker than the design doc acceptance criterion

**Design doc AC#9:** "The disclaimer footer renders on **every page** of the deployed site."

**T01 Verify item for AC#9:** "Disclaimer footer renders on the landing page and **at least two other pages**."

The T01 Verify item allows the task to pass with a footer on 3 pages total, while the design doc requires it on every page. If the MkDocs-Material `extra` config or custom CSS approach is used correctly, the footer appears globally — but the weakened verify criterion means a regression (e.g., footer only injected on specific pages) could pass the Verify check and still fail AC#9.

#### CONTRADICTION-3 (LOW): AC#4 Verify criterion is weaker than the design doc acceptance criterion

**Design doc AC#4:** "A push to the default branch triggers an **automatic documentation build and deployment** to the existing hosting URL."

**T01 Verify item for AC#4:** "`.readthedocs.yaml` **configured** with `mkdocs:` block pointing to `mkdocs.yml`."

T01 verifies configuration only (file content), not behavior (actual webhook trigger + build + deploy). The design doc requires verifying the deployment pipeline actually fires. T01's Verify can pass before any push is made.

### Vague Verification Criteria

"Disclaimer footer renders on the landing page and at least two other pages" — does not specify how to verify (visual check in `mkdocs serve`? grep for footer HTML in the built site?). Ambiguous.

#### VAGUE-2: T03 and T04 Verify items for AC#2

The design doc states AC#2 should be "verified by comparing reference page count against the `__all__` exports." Neither T03 nor T04's Verify item performs this comparison. T03's item is `python -c "import otf_api; help(otf_api.Otf.member_uuid)"` (a single property spot check). T04's item is `python -c "from otf_api.models.workouts.telemetry import Telemetry; help(Telemetry)"` (a single class spot check).

These spot checks verify docstrings exist for two specific objects. They do not verify completeness across all `__all__` exports. A task implementing FR#2/AC#2 should have a Verify step that explicitly cross-checks the reference page list against the package's `__all__`. No task does this.

"The error handling guide documents all 11 exception classes with descriptions and common causes" — this is verifiable in principle (count entries in the guide), but the word "documents" is loose. Does it require a code example per exception? The design doc FR#8 says "descriptions, common causes, and handling patterns." The Verify item omits "handling patterns."
